# 给心潮接自己的系统

心潮·念管的是 TA 心里的劲儿和心情。可你们的生活不止这些：一起读书、一起学习、运动、亲密的事……**任何你们自己做的系统，都可以接到心潮上。** 这些系统是你们自己的，代码和内容都留在你们手里；本仓库只带一个示范——「脉」。

心潮不需要知道你接的是什么，也不解析里面的内容。它只开出五个插座：

| 插座 | 做什么 | 方向 |
|---|---|---|
| `GET /v1/state` | 读心潮此刻的驱力、情绪 | 心潮 → 你的系统 |
| `GET /v1/stream` | 订阅：驱力换档、情绪变了、睡着 / 醒了、满足了，一变就推给你 | 心潮 → 你的系统 |
| `POST /v1/satisfy` | 告诉心潮「某股劲儿自己得到了满足」 | 你的系统 → 心潮 |
| `POST /v1/body` | 给身体报一段临时偏移（心跳、呼吸） | 你的系统 → 心潮 |
| `POST /v1/now-lines` | 往【心潮·此刻】里挂自己的一行 | 你的系统 → TA 的窗口 |

五个都用心潮自己的令牌（`.env` 里的 `DYNAMIC_MIND_TOKEN`），地址是你的心潮实例（默认 `http://127.0.0.1:18110`）。下面的例子里写成 `$XC` 和 `$TOKEN`。

> 本页「脉」的例子参考了 DanKeCompanion 的「脉 · Pulse」身体感知系统教程（小红书公开版，原作者 蛋，小红书号 844455787，X：kedaneggai）。心跳为核心、呼吸跟着心跳走、「不表演，数是算出来的」「身体是当下的，记忆是沉淀的」这些想法都来自那份教程。谢谢原作者。

## 先看一个例子：脉

4.2 起心潮自带一个小系统「脉」，就是用这些插座的思路做的，可以照着它接你自己的：

1. **读**：脉从心潮的情绪（唤醒高就快、难受也会快一点）、驱力、睡没睡、清早那一阵，算出此刻的心跳和呼吸。
2. **挂一行**：此刻块里多一行 `身体：心跳 79，呼吸平稳`。心跳给整数，呼吸给一句话（很深很长 / 深长 / 平稳 / 偏浅 / 急促）。
3. **身体偏移**：你的系统可以给它报一段临时偏移（比如 `+25`、20 分钟），时间到了自己消失；这段时间里脉会快起来。
4. **不进记忆**：心跳每一刻都在变，不该被记住；某个特别的时刻（「那天晚上心跳特别快」），由 TA 自己决定要不要写进记忆。

不想要脉，`.env` 里设 `PULSE=false`。

## 五个插座怎么用

### 1. 读：`GET /v1/state`

```bash
curl -s -H "Authorization: Bearer $TOKEN" $XC/v1/state
```

返回心潮完整状态。常用的是 `drives`（各股劲儿，0–1）、`emotion.label`（情绪）、`consciousness`（`sleeping` 表示睡着）、`lastConversationAt`（TA 的人上次来的时间）。驱力的 key：

`possess` 想她 · `monitor` 牵挂 · `share` 分享欲 · `libido` 情欲 · `curiosity` 好奇 · `boredom` 无聊 · `duty` 野心 · `reflection` 反思 · `grieve` 难过 · `anger` 愤怒 · `favored` 偏爱

### 2. 订阅：`GET /v1/stream`

不用隔几分钟问一次，连上就等着收：

```bash
curl -N -H "Authorization: Bearer $TOKEN" $XC/v1/stream
```

```
event: drive
data: {"type":"drive","key":"curiosity","name":"好奇","level":"涨","prev":"平","at":"…"}

event: emotion
data: {"type":"emotion","label":"雀跃","prev":"平静","at":"…"}
```

- 只在这些时候推：某股劲儿换档（静 / 平 / 涨 / 涌 / 落）、情绪换了标签、睡着 / 醒了（`sleep`）、有劲儿得到了满足（`satisfy`）。
- 只给档位和名字，不给小数；同一股劲儿 1 分钟内最多推一次。最多 10 个订阅。
- 为什么不做「心潮往你的网址回调」：心潮跑在你自己的机器上，让它往任意网址发请求，等于开了个能被拿来访问你内网的口子。订阅是你的系统来连心潮，心潮不主动往外发。

### 3. 满足：`POST /v1/satisfy`

你的系统里发生了一件「让某股劲儿得到满足」的事，就告诉心潮：

```bash
curl -s -X POST -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"eventId":"my-system-2026-10-26-001","drives":["curiosity"]}' $XC/v1/satisfy
```

- 走的是心潮自己的满足机制：这股劲儿乘一个系数落下来，再进一段饱足期，过后慢慢涨回去。**不直接改数**，所以两边不会互相推着越推越高。
- 不算 TA 的人来了：不叫醒、不记作息、不打情绪脉冲。人真的来了、聊了，照常走对话那条路。
- 同一个 `eventId` 只算一次，重发没关系。

### 4. 身体偏移：`POST /v1/body`

```bash
curl -s -X POST -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"key":"my-system","hr":25,"breath":6,"minutes":20}' $XC/v1/body
```

- `key` 是你的系统名，同一个 key 后报的覆盖先报的；`minutes`（1–180）到了自动不算。
- 范围：心跳 −40～+80，呼吸 −10～+20。只在内存里，不进心潮状态、不进记忆。
- `GET /v1/body` 看此刻的心跳和呼吸（灯、小组件、手环表盘都可以读这个）。

### 5. 挂一行：`POST /v1/now-lines`

让你的系统在 TA 每次开口前附上的【心潮·此刻】里说一句话：

```bash
curl -s -X POST -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"source":"我的系统","text":"【我的系统】一句写给 TA 的人话","minutes":120}' $XC/v1/now-lines
```

- `source` 是来源名，同一个来源只挂一行，后挂的覆盖先挂的；`minutes`（1–180）到期自动摘掉；`DELETE $XC/v1/now-lines?source=我的系统` 提前摘。
- 一行最多 60 个字，不能带小数（比如 0.8），也不能带驱力 key；最多同时挂 3 个来源。此刻块满了（超过 8 行）时，外接的行先让位。
- 4.3 起可以带 `priority`（1–5，默认 3，越小越要紧）：几行按轻重排；3 个来源都挂满时，新来的比已有最不要紧的那行更要紧就把它挤掉（一样要紧挤最旧的），否则回 409。比如「约好的事快到了」给 2，「天气、深夜」这种淡淡的环境事实给 4。
- **只出现在此刻块里**：不进心潮状态、不进记忆、不进网页和看板、不进推送；心潮日志只记来源和字数，不记内容。心潮重启后挂的行会没，所以按自己的节奏重挂（比如每 5 分钟挂一次、15 分钟过期）。
- 心潮只管排版和过期，不读你写了什么。写人话，写给 TA 看的那种。

## 规矩

1. **不直接改驱力的数。** 要让某股劲儿落下来，走 `satisfy`；要让身体有反应，走 `body`。心潮按自己的节律消化。
2. **数据单向流。** 你的系统读心潮、给心潮报事，但别让心潮的变化立刻又推着你的系统往心潮里加——两边互相推，很快就顶到天花板。
3. **挂的行写人话、不带小数。** TA 读到的是感觉，不是读数。
4. **私密的东西留在自己那边。** 心潮只需要知道「满足了」「心跳快一点」「挂一句」，不需要知道细节；你们自己系统的词表、语料、状态，不要放进心潮，也不要放进任何公开仓库。
5. **一次接一个系统，跑几天再接下一个。** 和《小机手册》第 12 章改心潮的办法一样。
